## 失败与修正

1. 初版视觉树读取属性遇到 #1009，截图本身已生成但试验被标无效。改为对 Stage/显示对象属性逐项探测，空 filters 防护；修正版视觉6/6通过。该轮截图又揭示部分组合仍停在资源加载页，不能当成熟菜单的性能对照。
2. 因此加入 `MainMenu.loaded`、allLandsLoaded、textLoaded 和音乐计数的就绪门，采样从游戏资源就绪后预热。最终结果单独保存，旧轮次不计入最终通过数。
3. 复制资源时一度纳入根 `ru/`，发现它是约9GB历史目录，立即停止本轮唯一 prepare 进程并校验路径删除该失败副本；复制白名单改为实际运行资源和语言XML，排除该目录。未改源目录。
4. 沙箱临时目录不能正常读写/清理；离线测试改用项目 build/out 下临时目录。AIR 实机按既有经验使用正常桌面权限，唯一 app ID 与自有进程句柄保持隔离。
5. skill-verify 的脚本因当前 Python 缺 PyYAML 返回2；不视作通过。候选为两字段单行标量前言，改用明确记录的手工格式检查及程序化引用/安装回读检查。
6. 旧新档快照调用普通saveGame在教程中静默拒绝，尝试访问saveArr又遇internal成员#1069。改用公开getSave读槽位、saveGame(-2)写诊断自动快照，并在驱动侧验证PFEgame0.sol实际存在；失败不再被当作成功导出。
7. 深度遍历在4000节点上限前可能耗尽于菜单子树，漏掉stage顶层遮罩。改为广度遍历并优先列新增/类型变化/有意义命名的节点，实机读档对照找到了夹具色块；保留截断标记而非声称完整树。
8. Windows PowerShell首次技能安装脚本因UTF-8无BOM把中文文件名读错，发生在替换正式文件之前；补正确编码后旧指纹比对、备份与回读通过。

## 技能固化与限制

runtime-debug 增加卡顿/视觉异常触发、启动器只读清点、精确选组与归因路由；auto-testing 添加同一入口。详配方只保存在 `docs/AGENT-DEBUGGING.md`，避免复制多份。[安装回执](workflow-install.json)保存旧版备份及原/新指纹；[检查回执](workflow-checks.json)区分手工格式检查、文件安装/新引用核验、原有技能发现与尚未验证的独立新会话自动选择。

本会话已实际使用运行时取证、独立AIR实例、技能路由设计和检查方法；工具的合成验证不代表真实玩家异常已归因，也不证明新会话会自动选择新版流程。两技能新版标“待测试”。仅1.02验证；没有对所有正式模组、联机战斗、真实GPU残影或确定性输入回放做认证。后台QoS/其他进程、垃圾回收与随机场景仍是解释边界。

本轮采用 KB-000056（测量与截图分开）及 KB-000071（后台调度可能混淆）条件，没有改全机电源策略或其他进程。
