# 原启动器恢复与独立测试并行

2026-10-29。用户要求优先修复原启动器与多个对话发起测试的路径。本轮已本机安装；未修改游戏 SWF、正式模组名单或玩家存档。镜头性能候选仍待单独验收。

## 结论与实际改动

原 `Remains.exe`、`adl64.exe` 继承了游戏目录的 Low mandatory integrity label。实测正常运行器令牌为 Medium（8192），启动这些低标签 EXE 后子进程变为 Low（4096）。原启动器无法写普通临时路径，私有桌面启动器/AIR 在进入业务代码前返回 `0xC0000142`。不把此错误码普遍等同于标签问题：本机因果依据是同字节 ADL 仅改为显式 Medium 标签后，原失败样例通过39项检查。

先验证副本，再仅恢复四个明确入口文件为 Medium：根 `Remains.exe`、根 `adl64.exe`、`mods/ModLoader/RemainsModLauncher.exe`、`RemainsModScanner.exe`。四份 SHA-256、原有 DACL/所有者均不变；没有递归修改目录、临时目录或系统安全设置。来源标签为何出现尚未调查，不推定由某个客户端造成。授权是当前启动器/测试路径修复；本发现不授权自动处理其他 EXE。

测试副本仍会继承 Low，不能只修根入口。新增只读 `launch_integrity.py`：正常运行器启动工作区内低标签 ADL 副本时，必须与根 ADL SHA-256 完全一致，才复用普通标签的同版本原生宿主；隔离描述符、运行库参数、工作目录、应用 ID 和存储保持不变。不同版本/其他低标签程序明确拒绝，不改测试副本标签、不自动提权。`HiddenProcess` 与调试器显式可见分支均检查，并记录解析结果。

登记器此前所有游戏测试都独占、状态更新会改变排队顺序、已退出的中断记录一直保留占用。现在默认 `coexist` 功能计划使用 `game-coexist`，最多两个独立组并行；`benchmark` 与旧专用驱动默认 `game` 继续独占。相同/包含目录不能并行，申请顺序稳定，排队中的性能请求不会被后来功能请求挤占。默认等900秒后暂缓。

受管记录只有运行器及全部登记子进程已确认退出，且没有启动登记间隙，才自动释放；未知身份、活子进程、未登记完的启动及旧记录继续人工核对。慢进程查询移到数据库写锁外，应用结论前比对记录是否变化。不会终止其他进程。部署时共享表无其他活动或等待请求；早已载入旧工具的进程不会热更新，旧私有工具副本仍需改为导入正式工具。
